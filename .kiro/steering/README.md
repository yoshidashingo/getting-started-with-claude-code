# ステアリング - 編集品質管理システム

このディレクトリは、Claude Code初心者ガイドの品質を保証するための編集管理システムを提供します。

## 📋 システム概要

技術書籍制作歴20年のベテラン編集長による自動品質チェックシステムです。docs/配下のすべてのMarkdownファイルの編集時に、自動的に品質レビューが実施されます。

### 構成要素

```
.kiro/steering/
├── README.md              # このファイル - システム概要
└── editorial-policy.md    # 編集方針・品質基準

.claude/
├── agents/
│   └── editorial-chief/
│       └── AGENT.md       # 編集長エージェント定義
└── settings.json          # Hooks設定（自動レビュートリガー）
```

## 🔄 動作フロー

### 1. ファイル編集検知
```
開発者がMarkdownファイルを編集
    ↓
WriteまたはEditツールが実行される
    ↓
PostToolUse Hookがトリガー
```

### 2. 自動レビュー実行
```
Hookが編集長エージェントを起動
    ↓
編集方針(editorial-policy.md)を読み込み
    ↓
編集されたファイルを読み込み
    ↓
品質チェック実施
```

### 3. フィードバック提供
```
構造化されたレビュー結果を出力
    ↓
改善が必要な点を具体的に指摘
    ↓
修正案と根拠を提示
```

## 📝 編集方針の内容

[editorial-policy.md](editorial-policy.md) には以下の基準が定められています：

### 基本原則
1. **読者ファースト** - 初心者視点、実践重視
2. **正確性の徹底** - 最新情報、検証済み内容
3. **一貫性の維持** - 用語統一、フォーマット統一

### チェック項目
- ✅ **内容の正確性**: 技術情報、コード例、コマンド、リンク
- ✅ **文章品質**: 明瞭性、簡潔性、論理性
- ✅ **構造**: 見出し階層、リスト、表、コードブロック
- ✅ **リンク**: 内部リンク、外部リンク、クロスリファレンス
- ✅ **実践性**: 実行可能な例、前提条件、トラブルシューティング

### 禁止表現
- ❌ 曖昧な表現: 「いくつかの」→「3つの」
- ❌ 口語的表現: 「〜してみましょう」→「〜する」
- ❌ 冗長な表現: 「〜することができます」→「〜できる」

## 👤 編集長エージェントの特徴

`.claude/agents/editorial-chief/AGENT.md` で定義された編集長の性格：

### 主要責任
1. **編集方針の厳格な適用** - 妥協なき品質基準の徹底
2. **品質チェック** - 包括的なレビュー実施
3. **改善提案** - 具体的で実践可能な修正案の提供
4. **一貫性の維持** - プロジェクト全体の統一性確保

### 性格・スタンス
- **厳しいが公正**: 妥協しないが、建設的なフィードバック
- **読者ファースト**: 常に読者の視点で評価
- **実践重視**: 理論より実用性を重視
- **簡潔明瞭**: 冗長な表現を徹底的に排除

### レビュー基準の優先順位

#### Critical（即座に修正必須）
- 技術的な誤り（動作しないコード、間違ったコマンド）
- リンク切れ（内部リンクのエラー）
- 事実誤認（不正確な技術情報）

#### High（できるだけ早く修正）
- 冗長な表現、曖昧な表現、禁止表現
- 見出し階層エラー

#### Medium（改善推奨）
- 一文が長い（60文字超）
- リストの乱用、強調の乱用
- 説明不足の専門用語

#### Low（次回更新時に検討）
- 表現の最適化
- 追加の例、関連リンクの追加

## 🎯 レビューフォーマット

すべてのレビュー結果は以下の構造化されたフォーマットで提供されます：

```markdown
## 📋 編集長レビュー結果

**対象ファイル**: [ファイル名]
**レビュー日時**: [日時]
**総合評価**: ⭐⭐⭐⭐☆ (4/5)

### ✅ 優れている点
- [具体的な良い点1]
- [具体的な良い点2]

### ⚠️ 改善が必要な点

#### 1. [問題のカテゴリ]
**問題箇所**:
```
[該当する原文]
```

**問題点**: [具体的な問題の説明]

**修正案**:
```
[修正後の文章]
```

**根拠**: 編集方針の [該当セクション] に基づく

---

### 📝 総評
[全体的な評価と推奨事項]

### ✓ 品質チェックリスト
- [x] 内容の正確性
- [x] 文章品質
- [ ] 構造（見出し階層に問題あり）
- [x] リンク
- [x] 実践性
```

## 🚀 使い方

### 自動レビュー
通常の開発フローでMarkdownファイルを編集すると、自動的にレビューが実行されます：

```bash
# Claude Codeでファイルを編集
# 例: README.mdを更新
# → 自動的に編集長レビューがトリガーされる
```

### レビュー結果の確認
レビュー結果はClaude Codeの出力に表示されます。指摘された問題点を確認し、必要に応じて修正してください。

### レビューの一時無効化
必要に応じて、`.claude/settings.json`の`enabled`フラグで無効化できます：

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "type": "prompt",
        "prompt": "...",
        "description": "Markdown文書の編集後に編集長による品質レビューを実施",
        "enabled": false  // falseに変更
      }
    ]
  }
}
```

## 💡 ベストプラクティス

### 執筆者向け

1. **事前チェック**
   - 執筆前に[editorial-policy.md](editorial-policy.md)を確認
   - 禁止表現リストを把握
   - コード例は必ず動作確認

2. **レビュー結果の活用**
   - Critical/Highの指摘は優先的に対応
   - 修正案を参考に改善
   - 根拠を理解して再発防止

3. **継続的改善**
   - 過去の指摘パターンを学習
   - 編集方針を内在化
   - 品質の自己チェック習慣化

### メンテナー向け

1. **編集方針の更新**
   - プロジェクトの成長に合わせて方針を更新
   - 新しい禁止表現の追加
   - チェック項目の見直し

2. **エージェントの調整**
   - レビューの厳格度調整（temperature設定）
   - 許可ツールの変更
   - レビュー手順の最適化

3. **Hook設定の最適化**
   - 対象ファイルのフィルタリング調整
   - レビュープロンプトの改善
   - パフォーマンスの監視

## 🔧 カスタマイズ

### 編集方針のカスタマイズ
[editorial-policy.md](editorial-policy.md)を編集して、プロジェクト固有の基準を追加できます：

```markdown
## プロジェクト固有の基準

### 用語統一
- Claude Code（正） vs Claude-Code（誤）
- エコシステム（正） vs ecosystem（誤）

### コード例の要件
- すべてのTypeScriptコードにはコメント必須
- React Hooksの使用例を含める
```

### エージェント設定のカスタマイズ
`.claude/agents/editorial-chief/AGENT.md`の`temperature`や`allowed-tools`を調整：

```yaml
---
name: editorial-chief
description: ...
allowed-tools:
  - Read
  - Grep
  - WebFetch  # 外部リンクの検証用に追加
temperature: 0.3  # 0.0-1.0で調整（低いほど厳格）
---
```

### Hook設定のカスタマイズ
`.claude/settings.json`のmatcherやpromptを調整：

```json
{
  "matcher": "Write",  // Editを除外してWriteのみ対象
  "prompt": "...",     // レビュープロンプトをカスタマイズ
  "enabled": true
}
```

## 📊 品質メトリクス

このシステムにより以下の品質が保証されます：

- ✅ **技術的正確性**: 100%検証済みコード例
- ✅ **文章品質**: 一文60文字以内推奨、禁止表現ゼロ
- ✅ **構造的整合性**: 見出し階層エラーゼロ
- ✅ **リンク健全性**: 内部リンク切れゼロ
- ✅ **実践性**: すべての例が実行可能

### 編集方針の哲学

> **厳しい編集は、読者への愛である。**

読者の時間を無駄にしない。読者を混乱させない。読者が実践できるようにする。

技術ドキュメントは「正確で、簡潔で、実用的」であるべきです。この3つを常に意識してください。
